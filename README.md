# 📷 webcam-streamer

Легковесный, безопасный и высокопроизводительный сервис на **Go** для трансляции видеопотока с USB веб-камер в реальном времени.

Проект спроектирован с упором на минималистичность (**ноль внешних тяжелых фреймворков**) и максимальную производительность. Передача видео осуществляется по протоколу **MJPEG (Motion JPEG)**, что обеспечивает минимальную задержку и поддержку всеми современными браузерами «из коробки» (через стандартный тег `<img>`) без использования CGO, FFmpeg или OpenCV.

## 🔒 Безопасность и защита

Приложение разработано с учетом защиты от распространенных сетевых атак:
*   **Защита от уязвимостей конфигурации:** Сервер принудительно паникует и завершает работу, если в системе не заданы секреты или длина `JWT_SECRET` менее 32 символов (защита от перебора подписей).
*   **Безопасное хранение паролей:** Аутентификация администратора завязана на криптографически стойкие хэши **Bcrypt** с адаптивной задержкой времени проверки, что нивелирует тайминг-атаки (Timing Attacks).
*   **Защита от Брутфорса (Rate Limiting):** Встроенный middleware на базе `golang.org/x/time/rate` отслеживает входящие IP-адреса и блокирует запросы (HTTP 429 Too Many Requests) при превышении лимита попыток входа, логируя подозрительную активность.
*   **Автономность токенов:** Используется полноценный стандарт **JWT (RFC 7519)** с подписью **HMAC-SHA256**, реализованный силами стандартной библиотеки для исключения уязвимостей в сторонних зависимостях.

## 📡 Спецификация API Эндпоинтов

Все эндпоинты в случае ошибок возвращают консистентный JSON-ответ в формате:
```json
{
  "status": 401,
  "error": "Unauthorized"
}
```

### 1. Аутентификация (Публичный с защитой от брутфорса)
*   **URL:** `/api/login`
*   **Метод:** `POST`
*   **Тело запроса (`application/json`):**
    ```json
    {
      "username": "admin",
      "password": "your_secure_password"
    }
    ```
*   **Успешный ответ (HTTP 200 OK):**
    ```json
    {
      "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOi..."
    }
    ```

### 2. Получение списка доступных камер (Требуется JWT)
*   **URL:** `/api/cameras`
*   **Метод:** `GET`
*   **Заголовок авторизации:** `Authorization: Bearer <ваш_jwt_токен>`
*   **Успешный ответ (HTTP 200 OK):**
    ```json
    [
      {
        "id": "/dev/video0",
        "name": "Logitech HD Pro Webcam C920"
      },
      {
        "id": "/dev/video1",
        "name": "Integrated Camera"
      }
    ]
    ```

### 3. Переключение камеры «на лету» (Требуется JWT)
*   **URL:** `/api/cameras/switch`
*   **Метод:** `POST`
*   **Заголовок авторизации:** `Authorization: Bearer <ваш_jwt_токен>`
*   **Тело запроса (`application/json`):**
    ```json
    {
      "camera_id": "/dev/video1"
    }
    ```
*   **Успешный ответ (HTTP 200 OK):**
    ```json
    {
      "status": 200,
      "message": "Камера успешно переключена"
    }
    ```

### 4. Видеопоток MJPEG (Требуется JWT)
*   **URL:** `/api/stream`
*   **Метод:** `GET`
*   **Авторизация:** Токен принимается как в заголовке `Authorization`, так и в Query-параметре `/api/stream?token=<токен>` (для прямой интеграции в HTML-тег `<img src="...">`).
*   **Ответ:** Бесконечный стрим бинарных JPEG-кадров со специальным типом содержимого: `multipart/x-mixed-replace; boundary=frame`.

## 🧪 Руководство по тестированию

Благодаря инъекции интерфейсов бизнес-логика тестируется в полной изоляции без подключения реального оборудования. Тесты покрывают сценарии успешных авторизаций, генерацию/валидацию токенов, сбои оборудования и конкурентную обработку видеопотоков.

### Запуск тестов
Для обхода конфликтов кэша локального тулчейна и отключения предварительного статического анализа используйте команду:
```bash
GOTOOLCHAIN=local go test -vet=off -cover ./...
```

### Детальный анализ покрытия
Чтобы посмотреть, какие именно строки кода покрыты тестами, сгенерируйте HTML-отчет:
1. Запустите сбор метрик:
   ```bash
   GOTOOLCHAIN=local go test -vet=off -coverprofile=coverage.out ./...
   ```
2. Откройте интерактивную визуализацию в браузере:
   ```bash
   go tool cover -html=coverage.out
   ```
*В открывшемся окне зеленым цветом будут подсвечены строки, успешно задействованные в юнит-тестах.*

## 🚀 Удаленный деплой по SSH (Production)

Развертывание проекта полностью автоматизировано через `Makefile`. При каждом новом деплое система запрашивает новый пароль в консоли и **динамически генерирует уникальный Bcrypt-хэш и новый криптостойкий секрет JWT** на удаленном сервере.

### 1. Первоначальная настройка службы (Выполняется 1 раз)
Команда компилирует бинарник, отправляет его по SSH и регистрирует приложение как системного демона (`systemd`) в вашей Linux-системе:
```bash
make setup-service SERVER_IP=ваш_ip_сервера SERVER_USER=root
```

### 2. Регулярный деплой обновлений
Сборка сжатого продакшн-бинарника (с флагами `-w -s`, уменьшающими вес до ~8-10 МБ), отправка на сервер, обновление переменных окружения и мягкий безопасный перезапуск процесса:
```bash
make deploy SERVER_IP=ваш_ip_сервера SERVER_USER=root
```

## 📊 Управление службой на сервере

После настройки через `Makefile` вы можете управлять стримером на удаленном Linux-сервере стандартными командами:

*   **Просмотр логов направления запросов и логов безопасности в реальном времени:**
    ```bash
    journalctl -u webcam-streamer.service -f -n 100
    ```
*   **Проверить статус работы сервиса:**
    ```bash
    systemctl status webcam-streamer.service
    ```
*   **Остановка / Перезапуск трансляции:**
    ```bash
    systemctl stop webcam-streamer.service
    systemctl restart webcam-streamer.service
    ```
