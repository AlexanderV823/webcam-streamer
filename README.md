# 📷 webcam-streamer

Высокопроизводительный и безопасный сервис для стриминга живого видеопотока с USB-веб-камер в режиме реального времени. Бэкенд написан на **Go (с нативной интеграцией V4L2)**, фронтенд проксируется через **Nginx с SSL-шифрованием**, защитой от утечек памяти и ограничением частоты запросов (Rate Limiting).

---

## 🚀 Архитектурные особенности системы

* **Нативный захват YUYV 4:2:2**: Сервис разработан для работы с камерами, не поддерживающими MJPEG на аппаратном уровне (чипы USB2.0 PC CAMERA, Vimicro и др.).
* **Конвертация на лету**: Go-бэкенд захватывает сырые макропиксели `YUYV`, упаковывает их в `RGBA` и на лету сжимает в `JPEG` силами процессора, выдавая клиенту оптимизированный MJPEG-поток.
* **Изоляция памяти**: Реализовано принудительное циклическое освобождение кольцевых буферов ядра Linux V4L2 (`ReleaseFrame`), что предотвращает падение потока и утечки через ~12 секунд трансляции.
* **Безопасный деплой**: Пароль администратора автоматически хешируется в Bcrypt на этапе установки, а сессии защищены JWT-токенами.

## 🔒 Безопасность и защита

Приложение разработано с учетом защиты от распространенных сетевых атак и оптимизировано для работы в связке с Reverse Proxy:
*   **Двухуровневая защита от Брутфорса (Rate Limiting):** Ограничение частоты запросов вынесено на уровень веб-сервера Nginx (зона `limit_req_zone`). Это позволяет отсекать распределенные атаки перебора паролей на дальних подступах, защищая Go-приложение от ресурсоемких вычислений Bcrypt.
*   **Защита от подмены IP (IP Spoofing):** Функция извлечения сетевого адреса в Go-мидлварях жестко завязана на заголовок `X-Real-IP`, который авторитарно перезаписывается Nginx из фактического TCP-соединения. Хакер не может обойти лимиты или подменить логи путем ручной отправки заголовков `X-Forwarded-For`.
*   **Защита от уязвимостей конфигурации:** Сервер принудительно завершает работу (Fail-Fast), если в системе не заданы секреты или длина `JWT_SECRET` менее 32 символов (защита от перебора подписей по словарям).
*   **Безопасное хранение паролей:** Аутентификация администратора проверяется по криптографически стойким хэшам **Bcrypt** с адаптивной задержкой времени, что полностью нивелирует тайминг-атаки (Timing Attacks).
*   **Автономность токенов:** Используется стандарт **JWT (RFC 7519)** с подписью **HMAC-SHA256**, реализованный силами стандартной библиотеки Go для минимизации внешних зависимостей. При закрытии вкладки пользователем горутины стрима и TCP-соединения мгновенно и безопасно завершаются на бэкенде через контексты (`context.Context`).
*   **Защита диска от переполнения (Авторотация логов):** Все логи пишутся в реальном времени параллельно в stdout и в файл `log.txt`. При превышении лимита `MAX_LOG_SIZE_MB` из `.env` кастомный ротатор на чистом Go атомарно сбрасывает размер файла, предотвращая отказ сервера из-за переполнения хранилища.

## 📡 Спецификация API Эндпоинтов

Все эндпоинты в случае ошибок возвращают консистентный JSON-ответ в формате:
```json
{
  "status": 401,
  "error": "Unauthorized"
}
```

### 1. Аутентификация (Публичный с защитой от брутфорса)
*   **URL:** `/api/login`
*   **Метод:** `POST`
*   **Тело запроса (`application/json`):**
    ```json
    {
      "username": "admin",
      "password": "your_secure_password"
    }
    ```
*   **Успешный ответ (HTTP 200 OK):**
    ```json
    {
      "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOi..."
    }
    ```

### 2. Получение списка доступных камер (Требуется JWT)
*   **URL:** `/api/cameras`
*   **Метод:** `GET`
*   **Заголовок авторизации:** `Authorization: Bearer <ваш_jwt_токен>`
*   **Успешный ответ (HTTP 200 OK):**
    ```json
    [
      {
        "id": "/dev/video0",
        "name": "Logitech HD Pro Webcam C920"
      }
    ]
    ```

### 3. Переключение камеры «на лету» (Требуется JWT)
*   **URL:** `/api/cameras/switch`
*   **Метод:** `POST`
*   **Заголовок авторизации:** `Authorization: Bearer <ваш_jwt_токен>`
*   **Тело запроса (`application/json`):**
    ```json
    {
      "camera_id": "/dev/video1"
    }
    ```

### 4. Видеопоток MJPEG (Требуется JWT)
*   **URL:** `/api/stream`
*   **Метод:** `GET`
*   **Авторизация:** Токен принимается как в заголовке `Authorization`, так и в Query-параметре `/api/stream?token=<токен>` (для прямой интеграции в HTML-тег `<img src="...">`).
*   **Ответ:** Бесконечный стрим бинарных JPEG-кадров со специальным типом содержимого: `multipart/x-mixed-replace; boundary=frame`.

## 🧪 Руководство по тестированию

Благодаря инъекции интерфейсов бизнес-логика тестируется в полной и чистой изоляции без подключения реального оборудования. Тесты покрывают сценарии успешных авторизаций, работу с токенами, сбои оборудования, вкомпилированную статику, ротацию логов на диске и конкурентную обработку видеопотоков.

### Запуск тестов

```bash
go test -cover ./...
```

Для обхода конфликтов кэша локального тулчейна и отключения предварительного статического анализа используйте команду:
```bash
GOTOOLCHAIN=local go test -vet=off -cover ./...
```

### Детальный анализ покрытия
Чтобы посмотреть, какие именно строки кода покрыты тестами, сгенерируйте HTML-отчет:
1. Запустите сбор метрик:
   ```bash
   go test -coverprofile=coverage.out ./...
   ```
2. Откройте интерактивную визуализацию в браузере:
   ```bash
   go tool cover -html=coverage.out
   ```

## 🚀 Безопасный рабочий деплой на сервер в одну строку

Развертывание проекта полностью автоматизировано и происходит **напрямую на стороне сервера**. Секреты (включая `JWT_SECRET`) никогда не передаются по сети и не сохраняются в Git-репозитории.

При первом деплое скрипт автоматически определит внешний IP-адрес роутера, сгенерирует криптостойкий JWT-ключ и откроет интерактивный редактор `nano` прямо в окне вашего терминала. В `nano` вы вводите **пароль обычным текстом** (в поле `ADMIN_PASSWORD`), а скрипт автоматически перехватит его, преобразует в безопасный **Bcrypt-хэш** с помощью Docker и запишет в закрытый файл `.env`.

### Команда для запуска на удаленном сервере:
Подключитесь к вашему серверу по SSH и выполните следующую связку команд (замените URL на ваш актуальный репозиторий):

```bash
curl -sSLO https://raw.githubusercontent.com/AlexanderV823/webcam-streamer/main/deploy.sh && chmod +x deploy.sh && ./deploy.sh
```

Полная очистка сервера:

```bash
cd /opt/ && sudo rm -rf ./webcam-streamer && cd ~ && rm -f deploy.sh
```

### 📊 Управление и мониторинг
*   Благодаря правилу `restart: always` в Docker Compose, контейнеры **автоматически запускаются при старте операционной системы** сервера.
*   При каждом новом деплое скрипт автоматически производит очистку системы (`docker image prune -f`), удаляя старые образы-сироты (`<none>`) и освобождая дисковое пространство.
*   Посмотреть статус работы контейнеров: `sudo docker compose ps`
*   Посмотреть логи запросов в реальном времени: `sudo docker compose logs -f`
*   Лог-файл приложения проброшен на хост-машину и доступен по адресу: `/opt/webcam-streamer/log.txt`

## 🔌 Аппаратная совместимость и решение проблем (V4L2 / YUYV)

Так как бэкенд взаимодействует с оборудованием через прямые системные вызовы Linux V4L2 на базе библиотеки `blackjack/webcam`, при развертывании на некоторых конфигурациях ядра могут возникать аппаратные нюансы.

### 1. Ошибка `inappropriate ioctl for device` на старте
*   **Причина:** Большинство встроенных или старых внешних веб-камер (класса `USB2.0 PC CAMERA`) аппаратно **не поддерживают формат MJPEG**, отдавая только сырой поток `YUYV`. Попытка форсировать MJPEG через `ioctl` отклоняется ядром Linux.
*   **Решение:** Бэкенд переведен на нативный захват `YUYV 4:2:2` (разрешение `640x480`). Драйвер автоматически транскодирует макропиксели в пространство `RGBA` и упаковывает в `JPEG` силами процессора.
*   **Изоляция в Docker:** Убедитесь, что в `docker-compose.yml` у сервиса приложения включены флаги прямого доступа к шине хоста:
    ```yaml
    privileged: true
    user: "root"
    ```

### 2. Стрим зависает или пропадает через 10–12 секунд (Ошибка Nginx 499)
*   **Причина:** Подсистема Video4Linux2 выделяет для камеры ограниченный кольцевой буфер памяти в ядре. Если приложение вычитывает кадры, но не возвращает их обратно в очередь, за 12 секунд буфер полностью забивается, и камера перестает выдавать новые кадры. Nginx рвет соединение по таймауту (`499`).
*   **Решение:** В функции `ReadFrame` реализовано явное копирование данных в локальный стек Go и принудительный вызов метода освобождения системной памяти ядра: `c.cam.ReleaseFrame()`.

### 3. Настройка прав доступа к видео-нодам
Для того чтобы Docker-контейнер мог отправлять `ioctl` вызовы к `/dev/video*`, скрипт деплоя автоматически инициализирует права доступа на хост-машине. В случае ручного переподключения камер выполните:
```bash
sudo chmod 666 /dev/video*
```
