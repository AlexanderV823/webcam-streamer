# Go WebCam Streamer (Clear Architecture + Docker + HTTPS)

Легковесный, безопасный и быстрый сервис на **Go** для трансляции видеопотока с USB веб-камер в реальном времени через защищенное **HTTPS (Nginx + Let's Encrypt)** соединение с ограничением доступа по **Basic Auth**.

Проект спроектирован по принципам **Чистой Архитектуры (Clear Architecture)**. Он полностью автономен, работает в Docker и осуществляет захват видео напрямую через системные вызовы Linux V4L2 (Video for Linux 2) без использования тяжелых внешних библиотек (CGO, OpenCV, FFmpeg). Трансляция работает по протоколу MJPEG и поддерживается любым современным браузером "из коробки" без дополнительных JS-плееров.

## 🚀 Особенности
- **Архитектура:** Изолированные слои (Domain, Usecase, Infrastructure, Delivery) позволяют легко менять бэкенд, фронтенд или системные драйверы.
- **Безопасность:** Доступ к панели управления и видеопотоку закрыт авторизацией (Basic Auth) на уровне Nginx. Данные авторизации настраиваются в `.env`.
- **Автоматический SSL:** Контейнер Certbot автоматически выпускает и каждые 12 часов проверяет/продлевает бесплатный валидный сертификат от Let's Encrypt.
- **Проксирование без задержек:** Nginx настроен на работу с MJPEG (отключено внутреннее кэширование и буферизация потока).
- **Легковесность:** Итоговый Docker-образ бэкенда весит всего около 20–25 МБ и потребляет до 20 МБ ОЗУ в режиме стриминга.

## 🛠 Требования к системе (Debian Server)

Перед запуском убедитесь, что у вас направлена **A-запись вашего домена** на публичный IP-адрес вашего Debian-сервера.

Скрипт развертывания автоматически установит Docker, Docker Compose, `openssl` и `v4l-utils` (если они отсутствуют), но для работы с системными вызовами V4L2 требуется запуск от имени `root` (что уже заложено в `deploy.sh` и `docker-compose.yml` через режим `privileged`).

## 📦 Быстрый старт и развертывание

Вся процедура установки, настройки и генерации секретов полностью автоматизирована.

### Шаг 1. Сделайте скрипт исполняемым
```bash
chmod +x deploy.sh
```

### Шаг 2. Запустите скрипт развертывания с правами sudo
```bash
sudo ./deploy.sh
```

### Шаг 3. Интерактивная настройка
1. Скрипт проверит окружение и автоматически создаст файл `.env` из шаблона.
2. В терминале откроется текстовый редактор **nano**. Отредактируйте параметры:
   - `DOMAIN_NAME` — укажите ваш реальный домен (например, `://yourdomain.com`).
   - `AUTH_USER` и `AUTH_PASSWORD` — задайте логин и пароль для доступа к камерам.
   - Нажмите `Ctrl+O`, затем `Enter` для сохранения, и `Ctrl+X` для выхода из редактора.
3. Скрипт автоматически запустит **валидацию**. Если вы забыли изменить дефолтные значения или оставили поля пустыми, скрипт укажет на ошибку и предложит отредактировать файл заново.
4. После успешной валидации скрипт сам сгенерирует зашифрованный файл паролей `.htpasswd`, запустит временный Nginx, запросит сертификаты у **Let's Encrypt** и поднимет всю производственную инфраструктуру в фоне.

### Шаг 4. Проверка работы
Откройте браузер и перейдите по адресу:  
🔗 **`https://<ВАШ_ДОМЕН>`**

*Введите логин и пароль, указанные вами в `.env`.*

## 📊 Мониторинг и управление

Все команды выполняются в корневой директории проекта, где находится файл `docker-compose.yml`:

- **Просмотр логов бэкенда (Go) в реальном времени:**
  ```bash
  docker compose logs -f webcam-streamer
  ```
- **Просмотр логов веб-сервера (Nginx) и попыток авторизации:**
  ```bash
  docker compose logs -f nginx
  ```
- **Остановка всех сервисов:**
  ```bash
  docker compose down
  ```
- **Принудительная пересборка и запуск:**
  ```bash
  docker compose up --build -d
  ```

## 🔧 Возможные проблемы со стримингом и их решение

### 1. Ошибка `v4l2 init failed: inappropriate ioctl for device`
В Linux современные USB-камеры регистрируют в системе несколько индексов устройств (например, `/dev/video0` и `/dev/video1`). Один из них предназначен для видеопотока, а второй — мета-устройство для передачи служебной технической информации (форматы, глубина резкости и т.д.). 
- **Решение:** Если вы выбрали камеру из выпадающего меню, но трансляция не началась, а в логах `webcam-streamer` появилась эта ошибка — просто выберите в веб-меню соседний индекс этого же устройства (например, `video0` вместо `video1`).

### 2. Список камер пуст (Docker не видит устройства)
Убедитесь, что физическая камера подключена к серверу и распознана ядром Debian. Выполните на хосте:
```bash
v4l2-ctl --list-devices
```
Если устройства видны на хосте, но их нет внутри Docker, проверьте, что в файле `docker-compose.yml` у сервиса `webcam-streamer` не удалена директива `privileged: true`, которая отвечает за обход изоляции ядра и прямой доступ Go-приложения к шине USB.
