# Go WebCam Streamer

Легковесный и быстрый сервис на **Go** для трансляции видеопотока с USB веб-камер в реальном времени через защищенное **HTTPS** соединение. 

Проект построен по принципам **Чистой Архитектуры (Clear Architecture)**, не использует тяжелых внешних зависимостей (CGO, OpenCV, FFmpeg) и осуществляет захват видео напрямую через системные вызовы Linux V4L2 (Video for Linux 2). Трансляция работает по протоколу MJPEG и поддерживается любым современным браузером "из коробки".

## 🚀 Особенности
- **Минимальный размер:** Бинарный файл весит ~6–8 МБ.
- **Низкое потребление ресурсов:** До 20 МБ ОЗУ в режиме стриминга.
- **Zero CGO:** Не требует сборки C-библиотек.
- **Интерфейс выбора:** Веб-меню для переключения между доступными `/dev/video*` устройствами.

## 🛠 Требования к системе (Debian Server)

Перед запуском убедитесь, что у вас установлены инструменты для работы с видеоустройствами:

```bash
sudo apt update
sudo apt install -y v4l-utils openssl
```

### Права доступа к камере
Пользователь, запускающий приложение, должен иметь права на чтение устройств `/dev/video*`. Добавьте пользователя в группу `video`:

```bash
sudo usermod -aG video \$USER
```
*Важно: после выполнения команды перезайдите в терминал (или перезапустите сессию SSH), чтобы права обновились.*

## 📦 Быстрый старт

### 1. Генерация SSL-сертификатов
Для работы HTTPS (требуется браузерами для стриминга медиа) сгенерируйте самоподписанный сертификат в корневой папке проекта:

```bash
openssl req -x509 -newkey rsa:4096 -keyout server.key -out server.crt -days 365 -nodes -subj "/CN=localhost"
```

### 2. Сборка и установка зависимостей
Сделайте синхронизацию модулей Go и соберите бинарный файл:

```bash
go mod tidy
go build -o streamer main.go
```

### 3. Запуск
```bash
./streamer
```

После этого откройте браузер и перейдите по адресу:  
🔗 **`https://<IP_ВАШЕГО_СЕРВЕРА>:8443`**

*(Поскольку сертификат самоподписанный, браузер покажет предупреждение безопасности. Нажмите «Дополнительно» -> «Перейти на сайт»).*

## 🏗 Структура проекта

Код разделен на независимые слои согласно Clear Architecture:

- `domain/` — Бизнес-сущности и интерфейсы (контракты для репозиториев и стримера).
- `usecase/` — Сценарии использования приложения (логика получения списка камер и потока).
- `infrastructure/v4l2/` — Низкоуровневая реализация интерфейсов под Linux с использованием V4L2.
- `delivery/http/` — HTTP/HTTPS транспортный слой, обработчики API и HTML/JS веб-интерфейс (`views.go`).
- `main.go` — Точка входа, сборка и связывание слоев (Dependency Injection).

## 🔧 Возможные проблемы и их решение

### Ошибка `v4l2 init failed: inappropriate ioctl for device`
Некоторые индексы `/dev/videoX` (обычно нечетные, например `video1`, `video3`) являются мета-устройствами для передачи метаданных камеры и не поддерживают захват видео. Если вы выбрали устройство, и поток не запускается — попробуйте выбрать соседний индекс в меню (например, `video0` вместо `video1`).
